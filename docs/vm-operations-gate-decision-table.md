# 日次ゲート判定表（段階 0・#60）

段階 0「mugi 環境での安定稼働確認（展開ゲート）」の日次判定を記録する表の型を固定する文書である。単位 AP-R0-2（#60 コメント 6734184861）で作成した。

## 正本の位置づけ

- ゲート条件そのものの正本は #60 本文と `docs/vm-operations-rollout.md` 段階 0 である。本書は条件を変更しない。条件の解釈を変える場合は本書ではなく正本側の手続きによる。
- 日次の判定結果の正本は #60 への転記コメントとする。手元ファイル `~/workspace/research-vm-resilience/stability-log.md`（日次 cron `vm-ops-stability-daily` が追記する）は正本の写しと位置づける。本書の例の表も写しであり、正本ではない。

## ゲート条件（#60 本文・rollout 段階 0 より）

次の全てを満たすこと。最短でも開始から 3 日間は観測する。

1. readiness チェックが連日 PASS する。
2. 起床遅延（24 時間ローリング、帰属分）が連日 100% 60 秒以内。
3. 実再起動が 3 回以上発生し、全て無人復旧する（boot 履歴に全 boot の記録が揃う）。
4. 誤 kill が 0 件、帰属できないリスナー停止が 0 件。
5. イベント欠落が 0 件。

## 表の型（列定義）

| 列 | 書き方 |
|---|---|
| 日付 | 観測日（JST）。1 日 1 行。 |
| 条件 1：readiness | PASS / FAIL と、FAIL の場合はどのチェックか（ほか何項目が PASS かを併記する）。24h 値が readiness 列にしかない日は、その値をここに置く（11-08 行の注意を参照）。 |
| 条件 2：起床遅延 24h | 24h ローリング値（帰属分）を n・中央値・p90・最大・60 秒以内の割合で書く。定常値（既知の構造変更の適用後区間に限った値）がある場合は内訳として併記する。合否の判定軸は 24h 値のままとする。 |
| 条件 3：実再起動・無人復旧 | 観測開始日以降の実再起動の累計件数と、全件無人復旧したことを書く。個別の boot 識別子が分かる場合は併記する。 |
| 条件 4：誤 kill・未帰属停止 | 当日の誤 kill 件数／帰属できない停止件数を「0／0」の形で書く。停止イベントがあった場合は帰属先（再起動／SDK rotation／意図的操作／executor draining 等）と回復までの時間を併記する。 |
| 条件 5：イベント欠落 | 進捗ドライブの三者突合（ハブ観測・event log・delivery の ack 状態）の当日結果を転記する。異常がなければ mugi 未 ack 件数と隔離中件数を書く。stability-log.md にはこの列の入力がないため、転記時は進捗ドライブの状態ファイルを入力とする。 |
| 連続性の扱い | PASS / FAIL の連続日数を事実として記録する（例：PASS 1 日目、FAIL 2 日目）。連続日数の数え方による充足判定は本書では行わない（「連日」についてを参照）。 |
| 異常の帰属 | 60 秒超過・readiness FAIL・停止イベントなど、異常があった項目ごとに、原因への帰属（何が・いつ・どの事象によるか）と、未確定の範囲を書く。帰属できないものは「未帰属」として残し、0 件としない。 |
| ゲート充足（累積） | その日時点の累積判定。未達の場合は未達の条件と、観測期間の残り（最短 2026-11-11 まで継続）を書く。 |

## 2026-11-08 行の列の使い方の注意

2026-11-08 行は、ほかの日と列の使い方が揃っていない。stability-log.md の 2026-11-08 行では「起床遅延 24h」列に 72h ベースラインの値（n=79・中央値 17.5 秒・最大 49.3 秒・100%）が入っており、24h 値（n=81・中央値 17.5 秒・最大 49.3 秒・100%）は readiness 列にある。

型の規則は次のとおりとする。

- 過去の行を転記する際は、元の値を書き換えない。原文のまま置き、注記で区別する。
- 2026-11-08 行については、条件 2 列に 72h ベースライン値を「72h ベースライン」と明記して置き、24h 値は条件 1 列に置く（上記の例のとおり）。
- 2026-11-09 以降の行は、条件 2 列に 24h 値を置く。定常値がある場合は内訳として併記する。

## 「連日」について

「連日」の数値定義は、#60 本文にも `docs/vm-operations-rollout.md` 段階 0 にもない。両者にあるのは「最短でも開始から 3 日間は観測する」「最短でも 2026-11-11 までは観測を続ける」という観測期間の記述のみである。

本単位では「連日」の解釈を確定しない。確定は判断事項として分離する。暫定の運用メモとして、連続日数は観測開始日（2026-11-08）からの連続日数として事実だけを記録し、充足判定には使わない。PASS / FAIL の連続は日付とともに「連続性の扱い」列へ記録する。

## 日次転記の手順

以後の日次転記は次の手順で行う。

1. 誰が：mugi が転記する。日次 cron `vm-ops-stability-daily` が手元 `stability-log.md` へ当日行を記録する（cron の記録は自動で、転記そのものは mugi の作業である）。
2. いつ：日次。`stability-log.md` の当日行が確定した後、翌日の定時回までに行う。ゲート到達時と異常発生時は、転記とあわせて所有者へ報告する（#60 コメント 6717293723 の記録方法による）。
3. どの入力から：`stability-log.md` の当日行（条件 1〜4 とゲート充足の入力）、進捗ドライブの状態ファイルの当日突合結果（条件 5 の入力）、および readiness・起床遅延の計測出力（数値の裏付け）。数値は入力の値を逐語で使い、書き換えない。
4. 転記先：本書の型に従って 1 行を作り、#60 へコメントとして転記する。転記前に #60 の `list-comments` を再読し、同一内容の転記がないことを確認する（重複転記をしない）。
5. 転記後：読み戻しで本文一致を確認し、コメント ID を控える。翌日以降の行は同じ型で積み上げる。
